# Financial Exception Log

## Overview

This log is generated by the Python financial-validation workflow. All new exceptions start as `Needs Review`.

## Exception schema

| Column | Description |
|---|---|
| `record_id` | Unique affected record identifier; Rule 4 uses `order_line_id`. |
| `rule_failed` | Validation rule that identified the record. |
| `observed_value` | Value or source attribute that triggered the rule. |
| `reason` | Explanation of the exception. |
| `resolution_status` | Investigation status. |

## Interpretation

- Alphanumeric product IDs are not treated as exceptions by themselves; many are valid retail products.
- Known transaction/service codes and gift vouchers are excluded from merchandise cost and inventory analysis.
- Below-cost checks apply only to positive-quantity merchandise sale lines and use simulated unit costs.
- Rule 4 is traceable at order-line grain through `order_line_id`; duplicate products within an order are not collapsed into one identifier.
- These checks are data-quality flags, not proof of actual financial loss. Costs are synthetic.
